# 05 复盘与回顾

## 1. 最难的问题

最有挑战的是**失败后的重规划与状态保留**，需要同时满足：

- 工具失败后不能把失败步骤记为成功；
- 切换替代方案时要保留与方案无关的素材检索结果；
- 绑定方案的脚本生成要重新执行；
- 一次性失败与持续失败要区分，才能体现「失败续跑」。

通过把「步骤结果」与「方案」绑定、并为素材检索设置跨方案复用规则，
最终让状态转换清晰可核对。

## 2. 学习收获

- 理解了 ReAct 不是简单的串行调用，关键在于**根据观察结果动态调整**。
- 体会到显式状态（state）与决策依据（rationale）对可评审性的重要性。
- 掌握了用标准库实现可复现的离线 Agent，以及为真实模型预留接口的做法。
- 认识到「无状态、无失败处理只能证明串行调用」，合理重规划才是高分点。

## 3. 不足与下一步

- 接入真实大模型验证决策效果，对比 Mock 与真实模型的差异。
- 补充截止时间与耗时的换算，做时间可行性校验。
- 增加更多替代方案与部分成功（部分素材可用）的组合场景。
- 视需要增加持久化存储，保留跨进程的方案数据。
