# 01 需求说明

## 1. 用户与目标

- **用户角色**：运营人员。
- **目标**：在给定**预算**与**截止时间**内，完成一份内容活动方案。

## 2. 输入与材料

| 输入项 | 说明 |
| --- | --- |
| 主题 theme | 内容活动的主题 |
| 预算 budget | 可花费的模拟单位上限，可能缺失 |
| 截止时间 deadline | 方案完成时限，可能缺失 |
| 合成素材 | `data/materials.json`，按主题检索 |
| 工具费用与耗时表 | `data/tools.json`，定义各工具在不同方案下的费用与耗时 |

## 3. 工具范围

本项目提供四个工具：

1. **素材检索 material_search**：按主题检索可用素材。
2. **脚本生成 script_generator**：基于素材生成活动脚本。
3. **成本估算 cost_estimator**：汇总方案费用与耗时，判断是否超预算。
4. **方案保存 plan_saver**：保存最终方案，幂等。

## 4. 交付结果

一次运行需返回：任务计划、步骤状态、工具结果、费用合计、已保存方案或
未完成原因。

## 5. 动态决策要求

模型必须根据**成本超限、工具错误或部分成功结果**调整计划、选择替代方案或
停止，并**保留已成功步骤的结果**。

## 6. 成功标准（验收点）

| 编号 | 验收点 | 期望行为 |
| --- | --- | --- |
| AC1 | 正常完成 | 走完方案并保存 |
| AC2 | 缺预算或截止时间 | 阻断并说明缺失项 |
| AC3 | 工具失败 | 调整计划，保留成功结果 |
| AC4 | 预算超限 | 切换替代方案；无可行方案则返回缺口 |
| AC5 | 重复执行 | 幂等，不产生新方案 |
| AC6（加分） | 失败步骤续跑 | 一次性失败后恢复，复用成功步骤完成 |

## 7. 边界与红线

- 不能把失败步骤记为成功。
- 无可行方案时返回未完成及缺口，不虚构方案。
- 不提交真实密钥或隐私数据。
